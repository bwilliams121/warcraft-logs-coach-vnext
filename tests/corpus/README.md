# Regression corpus (M9)

Deterministic, offline evidence for regression testing, with provenance that
says exactly what each file can and cannot prove.

This directory holds DATA and POLICY only. The machinery that validates and
executes it lives in `tests/support/corpus/`:

| File | Role |
| --- | --- |
| `contract.ts` | contract version, vocabularies, manifest schema, assertion registry |
| `loader.ts` | deterministic loading, integrity and lineage validation |
| `artifacts.ts` | synchronous payload access for layer tests (`committedEventArray(id)`) |
| `fight.ts` | artifact → normalized fight, granted exactly the retained coverage |
| `executors.ts` | dispatch: one registered kind → one executor in its owning layer |
| `executors/*.ts` | the executors, one module per owning layer |
| `harness.ts` | the one entry point: validate, select, execute, report |
| `report.ts` | coverage measurement and the declared evidence-gap list |

The manifest is regenerated by `scripts/corpus/build-manifest.mjs` (plain Node;
run it, then Prettier). The manifest is the artifact of record — the loader
validates it against the committed bytes on every run — and the generator is
how a deliberate change is made without hand-editing digests.

Nothing under `src/` may import any of it. `tests/contracts/m9a-corpus-layering.test.ts`
enforces that, and enforces that the corpus machinery reaches no transport,
clock, filesystem or environment.

## Layout

```text
tests/corpus/
    README.md              this document
    PROVENANCE-legacy.md   the M2–M8 investigation prose behind the migrated slices
    .gitattributes         pins LF under the root
    manifest.json          the index: every artifact, every case
    artifacts/             evidence bytes, digest-pinned, never rewritten by tooling
        wcl-events/        sanitized WCL event arrays and their derivations
        synthetic/         hand-authored payloads: pages, page sequences, edge events
```

`manifest.json` is formatted by Prettier like any other file. `artifacts/` is
listed in `.prettierignore`: an artifact's bytes are its identity, and no tool
may reflow them after the digest is taken.

Contract version: **2**. The loader reads exactly this version and rejects any
other (`CONTRACT_VERSION_UNSUPPORTED`). Bumping it is a reviewed migration.

| Version | Checkpoint | Retained coverage |
| --- | --- | --- |
| 1 | M9-A | a flat list of report-time ranges, applied to every category and actor alike |
| 2 | M9-B | `grants[]`, each with its own categories, actor scope and ranges; plus the `WCL_GRAPHQL_PAGE_SEQUENCE` payload kind |

A version-1 manifest is not a valid version-2 manifest — a flat range names
no categories and no actors — so the number moved. That is what the version
field is for: a manifest's meaning is fixed by its version, and a structural
change that kept the number would make the number say nothing. No version-1
corpus exists outside this repository, so there is no migration layer: the
loader rejects `contractVersion: 1` with an explicit error that names the
change and says to regenerate (`scripts/corpus/build-manifest.mjs`), and it
never reinterprets an older manifest.

## Two records, kept apart

### Artifact — bytes plus provenance

An artifact is one file and the account of where it came from:

- `artifactId`, `path` (corpus-relative, under `artifacts/`), `encoding`
  (`JSON` | `RAW_TEXT`), `payloadKind` (`WCL_EVENT_ARRAY` |
  `WCL_GRAPHQL_DATA` | `WCL_GRAPHQL_PAGE_SEQUENCE` | `JSON_VALUE` | `RAW_TEXT`)
- `sha256` and `byteLength` over canonical bytes (see *Integrity*)
- `provenance`:
  - `kind` — lineage classification (below)
  - `parentArtifactId` — for derivations
  - `source` — the capture the bytes come from: report code, fight, **report
    revision at capture**, source actor, encounter, difficulty, capture date,
    `gameVersion` / `logVersion`, ingestion scope, the exact retrieval query,
    the source capture's **pagination and completeness facts**
    (`eventsReturned`, `pagesRetrieved`, verbatim `nextPageTimestamp`, state,
    and where that evidence is written down), capture tooling identity, and
    whether the raw capture was retained (it never is; `.probe/` is gitignored)
  - `transformations` — every step between the source capture and this file,
    each with tooling, an invocation, a description, and the claims it
    **invalidates**
  - `retainedCoverage.grants[]` — each grant names `categories`, an
    `actorScope` (`null` = every actor; a list = those and no others, in M4's
    own sense) and `ranges`. Over those ranges, for those categories, the
    artifact holds EVERY event the source held for those actors. A category
    may appear in one grant only. Only grants may be granted as coverage when
    a fight is built from the artifact; a category no grant names gets none
  - `retainedFor`, `limitations`

Metadata that was not recorded is never `null` and never guessed. It is one
of three markers, because they mean different things:

| Marker | Meaning | Remedy |
| --- | --- | --- |
| `UNAVAILABLE` | could have been recorded, was not | re-capture with better tooling |
| `REDACTED` | recorded, deliberately removed for publication | none — it exists and is not here |
| `NOT_APPLICABLE` | has no meaning for this artifact | none |

Capture timestamps are corpus metadata. They never appear in analyzer output.

### Case — a claim about an artifact, owned by one layer

- `caseId`, `artifactId` — many cases may point at one artifact; the payload
  is never duplicated
- `owningLayer` — one of `WCL_TRANSPORT`, `NORMALIZATION`, `COMBAT_STATE`,
  `SPEC_ASSASSINATION`, `APPLICATION_SERVICE`, `PUBLIC_CONTRACT`. Each maps to
  real source roots in `contract.ts`, and a case may only use assertion kinds
  its layer owns (`CASE_ASSERTION_LAYER_MISMATCH`)
- `contractUnderTest` — the module/contract the claim is about
- `purpose` — **descriptive prose, never executed**
- `assertions` — **the executed part**: registered kinds with typed parameters
- `rationale` — `basis` from `OWNED_CONTRACT` | `VALIDATED_EVIDENCE` |
  `PINNED_AUTHORITY`, plus text. "This is what the code currently outputs" is
  deliberately not a basis
- `authority` — required when any assertion kind is authority-dependent:
  `authorityId`, `artifactRevision`, and the `requiredStateEvidence` the
  verdict needs. The revision must equal the committed authority artifact's
  (`CASE_AUTHORITY_REVISION_STALE` otherwise). Re-pinning SimulationCraft
  invalidates every authority-dependent expectation until it is re-verified
- `limitations`, `relatedTests`

## Lineage classification

Classification follows what was DONE to the bytes, not what they look like.

| `kind` | Meaning | Required | Forbidden |
| --- | --- | --- | --- |
| `REAL_CAPTURE` | bytes exactly as returned by Warcraft Logs | `source` | any transformation |
| `SANITIZED_CAPTURE` | a real capture after selection / redaction / remapping. Every event was observed | `source`, ≥1 sanitizing transformation | mutation, injection, removal |
| `DERIVED_FROM_CAPTURE` | a capture deliberately CHANGED to construct a condition. Not evidence the condition occurred | `parentArtifactId`, ≥1 deriving transformation that lists `OBSERVED_BEHAVIOUR` as invalidated | `source` (reached via the parent) |
| `SYNTHETIC` | hand-authored | — | `source`, `parentArtifactId` |

A mutated real capture is `DERIVED_FROM_CAPTURE`, never `SANITIZED_CAPTURE`.
The loader rejects the mislabel in both directions. No `REAL_CAPTURE` is
committed today: raw probe output stays in gitignored `.probe/`.

Transformation kinds: `SUBSET_SELECTION`, `IDENTIFIER_REMAP`,
`FIELD_REDACTION` (sanitizing); `VALUE_MUTATION`, `EVENT_INJECTION`,
`EVENT_REMOVAL` (deriving); `CREDENTIAL_SHAPE_SCAN`, `LEGACY_FIXTURE_COPY`
(neutral, recorded so the step is on file).

Claims a transformation can invalidate: `WINDOW_COVERAGE`, `ABSENCE_PROOF`,
`CROSS_EVENT_CONTINUITY`, `PAGINATION_BEHAVIOUR`, `OBSERVED_BEHAVIOUR`,
`ORIGINAL_IDENTIFIERS`.

**Trimming is a transformation.** A slice records `SUBSET_SELECTION` and
retains no coverage unless the selection PREDICATE provably kept everything
for some (categories, actors, range). "Every actor-19 cast, plus every aura
event targeting 19 or 21, in [A .. B]" retains CASTS for actor 19 and AURAS
for 19 and 21 over [A .. B], and nothing else; `--per-type 3` or `--indices`
retains nothing. Coordinates (report, fight, window) do not establish
completeness — the page facts do, and a slice that no longer contains the
page boundary cannot prove a pagination behaviour.

Of the seventeen committed artifacts, exactly three carry grants: the C3a,
C3c1 and D2 Assassination slices, whose in-place filters are recorded
predicates. The M5-C2 five-event slice does NOT, and the corpus therefore
pins the Vanish carry-forward on it as UNKNOWN / INSUFFICIENT_COVERAGE where
the legacy M5-C2 harness had granted coverage by declaration. That is the
corpus being stricter than the test it migrated, deliberately.

## Integrity

`sha256` and `byteLength` are computed over **canonical bytes**: the file's
UTF-8 bytes with `\r\n` folded to `\n`. That is the only transformation the
loader ever applies, it is applied on the way to the digest only, and it
cannot touch payload content — JSON forbids a raw carriage return inside a
string, so CRLF is always whitespace. It exists because `core.autocrlf=true`
checkouts would otherwise fail every digest on identical evidence.
`.gitattributes` pins LF as well.

A digest proves **identity**: these are the bytes the manifest describes. It
does not prove authenticity (that Warcraft Logs returned them) or completeness
(that nothing is missing). Those are provenance claims and are only as good as
the recorded transformations.

The loader never sorts, deduplicates, repairs or normalizes an artifact. Equal
timestamps, non-monotonic arrays, actor `0`, the `-1` sentinel and page
boundaries pass through untouched. Corpus STRUCTURE is validated; combat
validity is not — a deliberately malformed Warcraft Logs payload is a valid
artifact when a case tests its rejection. An artifact declared `JSON` must
parse; one declared `RAW_TEXT` need not.

## Loader rules

All rules run; every failure is reported with its code and the artifact or
case it was found on. `MANIFEST_MISSING`, `MANIFEST_NOT_JSON`,
`CONTRACT_VERSION_UNSUPPORTED` and `MANIFEST_SHAPE_INVALID` stop early because
nothing after them is meaningful.

| Rule | Code |
| --- | --- |
| ids unique | `ARTIFACT_ID_DUPLICATE`, `CASE_ID_DUPLICATE` |
| one file, one artifact | `ARTIFACT_PATH_DUPLICATE` |
| path relative, forward-slashed, no `.`/`..`, under `artifacts/` | `ARTIFACT_PATH_OUTSIDE_ROOT` |
| file present | `ARTIFACT_FILE_MISSING` |
| bytes match | `ARTIFACT_BYTE_LENGTH_MISMATCH`, `ARTIFACT_DIGEST_MISMATCH` |
| size ceilings | `ARTIFACT_TOO_LARGE`, `CORPUS_TOO_LARGE` |
| every file under `artifacts/` is referenced | `CORPUS_FILE_UNREFERENCED` |
| encoding/kind coherent, JSON parses, kind shape holds | `ARTIFACT_NOT_JSON`, `ARTIFACT_ENCODING_KIND_MISMATCH`, `ARTIFACT_PAYLOAD_KIND_MISMATCH` |
| lineage coherent | `PROVENANCE_*` (source required/forbidden, parent required/forbidden/unknown/cycle/synthetic, kind matches transformations, derivation admits `OBSERVED_BEHAVIOUR`, grants within the source window, no category in two grants, no grant without capture lineage) |
| case references resolve | `CASE_ARTIFACT_UNKNOWN` |
| assertions registered, typed, layer-owned, payload-compatible | `CASE_ASSERTION_KIND_UNKNOWN`, `CASE_ASSERTION_PARAMS_INVALID`, `CASE_ASSERTION_LAYER_MISMATCH`, `CASE_ASSERTION_PAYLOAD_KIND_MISMATCH` |
| authority pinned and current | `CASE_AUTHORITY_REQUIRED`, `CASE_AUTHORITY_UNKNOWN`, `CASE_AUTHORITY_REVISION_STALE` |

Determinism: artifacts and cases are returned in code-point order of their
ids, independent of manifest order and of how the filesystem listed files.
The committed corpus is bound at build time by `import.meta.glob`, so the
loader needs no `node:fs`, runs identically under plain Node and workerd, and
cannot see outside the corpus root. Digests use Web Crypto. There is no live
Warcraft Logs access and no fixture refresh path.

## Assertions

`contract.ts` registers every assertion kind: owning layer, outcome class,
compatible payload kinds, a strict parameter schema, and whether it is
`EXECUTABLE` (an executor exists in `executors.ts` and it counts as coverage)
or `DECLARED` (validated and reported, **not** counted). There is no free-form
or executable assertion in a manifest; adding a question means adding a kind,
an executor, and tests for both.

Outcome classes: `POSITIVE_FACT`, `NEGATIVE_FACT`, `UNKNOWN`,
`NO_AUTHORITY_AVAILABLE`, `UNSUPPORTED`, `REJECTION`, `PARITY`. `UNKNOWN` and
`NO_AUTHORITY_AVAILABLE` are separate classes and no kind accepts one in
place of the other; the UNKNOWN kind's `reason` parameter is the state
layer's own `UnknownReason` enum, which has no `NO_AUTHORITY_AVAILABLE`.

Kinds registered after M9-B — all EXECUTABLE, every one exercised by at
least one committed case:

| --- | --- | --- |

| `NORMALIZATION.INPUT_ORDER_PRESERVED` | NORMALIZATION | POSITIVE_FACT |
| `NORMALIZATION.TIMESTAMP_RUN_RETAINED` | NORMALIZATION | POSITIVE_FACT |
| `NORMALIZATION.ALL_TYPES_RECOGNISED` | NORMALIZATION | POSITIVE_FACT |
| `NORMALIZATION.SOURCE_ABSENCE` | NORMALIZATION | POSITIVE_FACT |
| `NORMALIZATION.SIDE_REFERENCE` | NORMALIZATION | POSITIVE_FACT |
| `NORMALIZATION.ATTACHED_RESOURCE_SIDE` | NORMALIZATION | POSITIVE_FACT |
| `NORMALIZATION.NO_ACTOR_REF_HOLDS` | NORMALIZATION | NEGATIVE_FACT |
| `NORMALIZATION.UNSUPPORTED_TYPE_COUNTED` | NORMALIZATION | UNSUPPORTED |
| `WCL_DECODE.EVENT_PAGE_OUTCOME` | WCL_TRANSPORT | REJECTION |

`SPEC_ASSASSINATION.DECISION_COVERAGE` runs the real
`analyzeObservedAssassinationDecisions` facade under the committed pinned
SimulationCraft authority, checks the facade ran under the revision the case
pins, and compares the facade's own comparison record — outcome, basis,
coverage, token, precision, blocker, rejection flag — verbatim. MATCH means
`AUTHORITY_COMPATIBLE_ONLY`. Nothing outside the pinned artifact can enter:
there is no port for parse performance, other players or log consensus.

`PUBLIC_CONTRACT.REST_MCP_PARITY` drives the real Worker and the real MCP
handler over production services with every Warcraft Logs port faked from the
artifact, and requires `JSON.parse(REST body)`, MCP `structuredContent` and
`JSON.parse(MCP text)` to be deeply equal and schema-valid, plus a few pinned
semantic facts. It needs workerd (bearer auth uses a Workers-only primitive),
so its gate lives in the `workers` project.

Raw-index addressing (`RAW_INDEX` selectors) is acceptable in the corpus and
nowhere else in this repository, because artifacts are digest-pinned and their
positions cannot move silently. Prefer a fact locator when one exists.

### How a fight is built from an artifact — the ONE coverage policy

Every fight over captured evidence, whether built by an executor or by a layer
test, is built by `tests/support/corpus/fight.ts`. There is no other place
captured events receive coverage. The window is the events' own timestamp
extent. Capability is granted only to the categories a capture can vouch for
(the ones `PROVENANCE-legacy.md` records as OBSERVABLE from sanitized
captures); each such category gets coverage from the ONE grant that names it,
with that grant's ranges and actor scope, or no coverage at all; a SYNTHETIC
artifact is granted no capability. A slice that retains no grant can prove no
absence — `combat-state.trimmed-slice-cannot-prove-absence` pins exactly that.

Layer tests reach it through `corpusFight(id)` / `corpusState(id)`, and — when
a test must change the events — `corpusFightFrom(id, events, premise)`, where
the PREMISE is one of a closed set the interpreter applies to the artifact's
own grants and never widens beyond what the premise's construction justifies:

| Premise | What the test did | What happens to the grants |
| --- | --- | --- |
| `TRUNCATED_BEFORE { cutMs }` | removed every event before the cut | clipped to start at the cut |
| `EVENT_REMOVED_AT { reportTimeMs }` | removed one event | clipped to end before that instant |
| `FANNED_ACTORS { sourceActorId, actorIds }` | cloned one actor's events per id | actor scope extended to the clones, where the source was in scope |

A premise is a stated test construction, never a claim about the capture.

**No test may declare coverage over captured events by hand.** The guard in
`tests/contracts/m9a-corpus-layering.test.ts` fails any module outside the
corpus machinery that reads captured raw events AND normalizes them itself
AND imports a fight builder — the three things needed to grant ad hoc
coverage — and pins that `normalizeEvents` is not exported (normalized captured
events leave `fight.ts` only inside a fight it built; `normalizationFactsOf`
returns counts). Hypothetical complete-coverage scenarios are built from
SYNTHETIC events over `syntheticFight`, labelled as a test premise, and are
never attributed to a capture.

Under this policy the D2, C3c1 and C3a slices reproduce every M5 result the
legacy harnesses had established by declaration (Garrote MATCH at Q, Deathmark
UNKNOWN, Envenom DIVERGENT_WORLDS, the 3/7 rejection, 5,746 ms Garrote
remaining, the Kingsbane anchor). Where a legacy declaration had exceeded the
evidence, the tests now say so: the five-event M5-C2 slice yields
`stealthed.rogue` UNKNOWN / INSUFFICIENT_COVERAGE at the Garrote decision
point; the proven-TRUE claim is capture-backed on the C3c1 slice and rule-tested
on a synthetic premise; the envenom-combo-points runs disclose ABSENT cast and
resource coverage rather than COMPLETE; and the aura-stack slice's
"nothing seen yet" is INSUFFICIENT_COVERAGE, not NO_OBSERVATION.

## The harness

`runCorpusHarness(selection, { runtime, execute? }, files?)` in `harness.ts`
is the one entry point:

```text
{ kind: "VALIDATE_ONLY" }                   validate the manifest and bytes, execute nothing
{ kind: "CASE", caseId }                    one case
{ kind: "LAYER", owningLayer }              every case one layer owns
{ kind: "ALL" }                             the complete executable corpus
```

`runtime` is stated by the caller — `NODE` or `WORKERD` — never sniffed.
Every registered kind declares the runtime it needs (`ANY`, or `WORKERD` for
`PUBLIC_CONTRACT.REST_MCP_PARITY`, which drives the real Worker and MCP
handler). A selection that includes a case the stated runtime cannot execute
is refused at SELECTION time, naming the cases and the runtime they need;
nothing is executed and nothing is reported for them. An environment mismatch
is never a result about the corpus, and coverage totals only ever come from a
runtime that could execute every selected case. `execute` is an injectable
executor so the harness's own exception handling is tested with a double.

It validates first and executes nothing on an invalid corpus. Cases and
assertions run in the loader's order and sequentially; two runs over the same
file table are structurally identical. Each assertion reports one of:

| Status | Meaning |
| --- | --- |
| `PASSED` | the executor ran and the layer produced what the case pins |
| `FAILED` | it did not — with case id, artifact id, owning layer, kind, assertion ordinal, expected and actual semantic results, and an evidence locator when the layer offered one |
| `NOT_EXECUTED` | the kind is DECLARED and has no executor; reported every run, never coverage |

There is no `SKIPPED`. `complete` is true only for zero FAILED and zero
NOT_EXECUTED; an executor that throws is a FAILED assertion carrying the
throw, never a crash and never a pass. A selection that names nothing is a
`SELECTION` failure, not an empty pass. `describeFailures(result)` renders
every non-passing assertion on a few lines; it never dumps a payload.

The gate is `tests/regression/m9b-corpus-gate.test.ts` (workers project, ALL:
31 cases, 74 assertions). `tests/unit/m9b-corpus-harness.test.ts` runs the four
Node-executable layers and the harness's own contract, including the Node
refusal of PUBLIC_CONTRACT and injected-executor exception handling;
`m9b-corpus-failure-demonstration.test.ts` proves that wrong expectations fail
understandably; `m9b-corpus-and-m5d2-agree.test.ts` pins the shared
coordinates between the M5-D2 corpus and the manifest. M9-C owns a dedicated
CI command for the gate.

### M5-D2 corpus and manifest: who owns what

`tests/support/m5d2-corpus.ts` owns the AUTHORITY SELECTION at a query point —
entry, precision, blocker class — driven step by step through the rotational
engine. The manifest owns the COMPARISON of an observed cast against that
selection through the M5 facade — MATCH / REJECTED / UNKNOWN, basis, and the
meaning of MATCH. The comparison carries the selection inside it, so where
both name the same observed cast the manifest's `authorityCoverage` and
`decisiveBlocker` must equal the D2 corpus's `expectedCoverage` and
`expectedBlockerClass`, under the same pinned revision, and must equal what
the engine actually produces. `m9b-corpus-and-m5d2-agree.test.ts` enforces all
three and proves neither definition claims the other's verdict.

## Sanitization policy

What a committed artifact must never contain:

- credentials, authorization headers, access tokens, client ids or secrets
- the test pool's sentinel credentials
- player names, realm names, or any `name` / `server` key on an event

What sanitization must preserve when the claimed behaviour depends on it:

- timestamps, exactly
- event order as returned, including same-timestamp order (it is evidence —
  see the M5-C3a entry in `tests/fixtures/wcl/events/PROVENANCE.md`)
- source/target/ability relationships and instance ids
- `-1` sentinels, actor `0`, `resourceActor`, `classResources` entries
- page boundary evidence (`nextPageTimestamp`) when a case is about pagination

Identifier remapping, when a future capture needs it, must be deterministic
and coherent — one mapping applied to every source, target and resource-actor
reference — recorded as `IDENTIFIER_REMAP` with `ORIGINAL_IDENTIFIERS`
invalidated.

Deliberate corruption is never mixed into a capture in place. It is a
separate `DERIVED_FROM_CAPTURE` artifact naming its parent and its mutation,
or a `SYNTHETIC` artifact with no lineage claim.

The existing slicer `scripts/sanitize-probe.mjs` remains the capture-to-slice
tool. It has no version field, so `tooling.revision` is `UNAVAILABLE` for the
slices it produced; giving it one is an M9-B tooling item.

## Storage policy

| Limit | Value | Basis |
| --- | --- | --- |
| per artifact | 512 KiB (`MAX_ARTIFACT_BYTES`) | the largest committed slice today is the ~226 KB M5-D2 corpus; a raw full-fight run is tens of MB and is never committed |
| whole corpus | 6 MiB (`MAX_CORPUS_BYTES`) | bounds what `import.meta.glob` eagerly bundles into a test module and what a clone carries |

Both are checked from measured canonical byte lengths, so the answer is the
same on every machine. There is no external storage: fixtures must work
offline and CI must never need a download or a credential. If M9-B's
population approaches the corpus ceiling, raise it deliberately in
`contract.ts` with the evidence, rather than storing artifacts elsewhere.

Legacy fixtures under `tests/fixtures/wcl/events/` are not migrated in M9-A.
Two were copied byte-for-byte into the corpus (`LEGACY_FIXTURE_COPY`), and
`tests/unit/m9a-corpus-seed-cases.test.ts` asserts each copy still equals its
original. Migrating the remaining fixtures and their importers is M9-B's.

## Regenerating the manifest

```powershell
node scripts/corpus/build-manifest.mjs
npx prettier --write tests/corpus/manifest.json
npx vitest run --project node tests/unit/m9b-corpus-manifest.test.ts tests/unit/m9b-corpus-harness.test.ts
npx vitest run --project workers tests/regression/m9b-corpus-gate.test.ts
```

A new slice from `scripts/sanitize-probe.mjs` lands under `artifacts/wcl-events/`
and prints its digest, byte length and tooling record; add an `artifact(...)`
entry with its source capture, transformations and grants, and a `kase(...)`
for each claim, then regenerate.
